# Document Compass · IBM RAG capstone

A document QA application with multiple PDF/TXT/Markdown uploads, reusable session libraries, page references, visible retrieved evidence and adjustable retrieval depth. Questions are independent; this is not a conversation-memory chatbot. Files must be readable text (scanned PDFs need OCR).

## Run in GitHub Codespaces

Use the **Codespaces terminal**, rather than Windows PowerShell:

```bash
cd /workspaces/IBM
git pull origin main
cd qa-capstone
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
HOST=0.0.0.0 python qabot.py
```

Open forwarded port **7860** in the Ports tab. Keep its visibility private. Upload a document, click **Build document library**, enter a question, then click **Find an answer**. Local mode returns actual matching excerpts using lexical similarity; it does not generate an LLM answer or fulfill the IBM embedding requirement.

Use a fresh Python 3.11–3.14 environment. Existing course notebook environments can contain incompatible old dependencies. The base dependencies were tested on Python 3.14. IBM optional dependency ranges are not a tested lockfile; check installation output and run the smoke check below.

## Full watsonx workflow

Stop the app with Ctrl+C, then:

```bash
python -m pip install -r requirements-ibm.txt
read -rsp 'IBM API key: ' WATSONX_API_KEY; echo
export WATSONX_API_KEY
read -rp 'IBM project ID: ' WATSONX_PROJECT_ID
export WATSONX_PROJECT_ID
export WATSONX_URL=https://us-south.ml.cloud.ibm.com
python -c "from langchain_ibm import WatsonxLLM, WatsonxEmbeddings; from langchain_chroma import Chroma; print('IBM imports OK')"
HOST=0.0.0.0 python qabot.py
```

Choose **IBM watsonx QA** and rebuild the library. Documents and questions are sent to your IBM service and calls may consume service allowance. Use your own valid project/key and region. If necessary, set `WATSONX_EMBEDDING_MODEL` and `WATSONX_LLM_MODEL` to models available in your account. The app does not collect keys in the browser or save them in code. Never commit credentials. `.env.example` documents configuration, but is not automatically loaded.

IBM mode creates a fresh Chroma collection, embeds the chunks, retrieves relevant passages and asks WatsonxLLM for an answer using those passages. Inline citations are generated by the LLM and may be incorrect: inspect the evidence table. The prompt asks the model to ignore instructions within uploaded documents, but cannot guarantee resistance to prompt injection.

## Six course tasks

| Task | Function in qabot.py | Evidence to capture |
|---|---|---|
| Load | `document_loader` / PyPDFLoader | PDF loader code |
| Split | `text_splitter` | Chunk size 1000, overlap 150, metadata preserved |
| Embed | `watsonx_embedding` | Code plus real first five embedding values |
| Store | `vector_database` | Chroma.from_documents code |
| Retrieve | `retriever` | as_retriever and actual query results in IBM mode |
| QA interface | `get_llm`, `retriever_qa`, `build_ui` | Running IBM interface screenshot named QA_bot |

The original lab used `RetrievalQA`. The modern app uses a LangChain prompt → WatsonxLLM → output parser runnable for the same retrieval-then-generation flow. `course_compat.py` includes a legacy `RetrievalQA` adapter if your lab specifically requires that class. Grading questions about the original lab refer to that lab; the modern implementation does not change the original course wording.

To capture the embedding evidence using real IBM output:

```bash
python -c "from qabot import watsonx_embedding; v=watsonx_embedding().embed_query('This is a document about scientific research.'); print('Dimensions:', len(v)); print('First five:', v[:5])"
```

Capture your actual running application and output. No generated screenshots or synthetic IBM embedding values are included. This package does not submit the assessment for you.

## Verification and limits

```bash
python -m unittest discover -s tests -v
```

Tests cover text loading, PDF metadata, chunking, retrieval ranking, no-match handling, library isolation and the QA runnable with stubbed cloud services. Live IBM credentials, model availability and generated answer quality require your account and were not tested. The app limits each file to 20 MB, ten documents and 2,000 chunks. Indexes remain in server memory; rebuilding makes a fresh collection and restarting the server clears memory. Clear library removes the session reference, not Gradio's temporary upload files. This is a private learning app, not a production document repository.

API references: [Gradio Blocks](https://www.gradio.app/docs/gradio/blocks), [WatsonxLLM](https://reference.langchain.com/python/langchain-ibm/llms).
